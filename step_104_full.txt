## Tier 1: Backend Features Already Built that Need UI Wiring (⚡ Highest ROI)
These capabilities are **already programmed and working in the backend**, but need to be visually presented on the frontend to impress judges:

### 1. Interactive Coercion Detection Chatbot (`brain.md` §S2.5, §S2.6)
* **What it is:** When a payment is **HELD**, instead of just showing a static screen, open an interactive 3-turn interview popup using `POST /api/guardian/converse`.
* **How it works:** The Guardian asks: *"Did someone call you on phone or WhatsApp asking for this money?"* It evaluates the user's typed reply to detect if they are being coerced or blackmailed, and can dynamically escalate `HOLD` → `BLOCK`.
* **Backend Ready:** [guardian.py](file:///c:/Users/lenovo/OneDrive/Desktop/kurhh/Kurukshetra/backend/app/api/guardian.py) & [llm_service.py](file:///c:/Users/lenovo/OneDrive/Desktop/kurhh/Kurukshetra/backend/app/services/llm_service.py).

### 2. Live ReAct Reasoning Chain Display (`brain.md` §10, §S2.6, §S2.12)
* **What it is:** A visual timeline showing the AI's step-by-step thinking (`react_reasoning_chain`):
  * *Step 1: Chosen Tool: detect_scam_patterns (Reason: Urgency detected in message)*
  * *Step 2: EARLY STOP (Reason: Risk already reached 100/100, no further tools needed)*
* **Why it matters:** Directly proves the system is an **Agent** (dynamic tool use + early stopping), not a static script.

### 3. Psychological Manipulation Radar Chart (`brain.md` §S2.6, §S2.12)
* **What it is:** A 4-axis visual meter or bar chart showing the scam's emotional exploitation scores:
  * 🔴 **Fear:** e.g., 0.85 (*"Power disconnected tonight"*)
  * 🟠 **Urgency:** e.g., 0.90 (*"Pay within 30 mins"*)
  * 🟡 **Authority:** e.g., 0.70 (*"Official Electricity Office"*)
  * 🟢 **Greed:** e.g., 0.00
* **Backend Ready:** Returned in `manipulation_profile` by [emotion_service.py](file:///c:/Users/lenovo/OneDrive/Desktop/kurhh/Kurukshetra/backend/app/services/emotion_service.py).

### 4. SHAP Feature Attribution Chart (`brain.md` §S2.6, §S2.12)
* **What it is:** A horizontal bar chart showing judges exactly what drove the ML anomaly score:
  * `Amount Ratio`: **76.9%**
  * `Velocity (1h)`: **19.2%**
  * `Reputation Deficit`: **3.9%**
* **Backend Ready:** Returned in `feature_attribution.contributions`.

### 5. Expand Payment Preset Scenarios (`brain.md` §27, §S2.9)
* Currently the payment screen only has 2 buttons (*Safe* & *Suspicious*).
* Add quick one-click buttons for the remaining scenarios from `brain.md`:

## Tier 3: "ADVANCED" Differentiator Features in `brain.md` §31, §32, §35

### 8. Interactive Scam Network Graph (`brain.md` §31, §33)
* **What it is:** An interactive visual graph (nodes & edges) showing:
  * Payer (`Aarav`) ──► Recipient (`support-verify@...`) ──► Flagged Mule Hub (receiving from 8 other victims).
* **Why it wins:** Judges love interactive graph visualizations showing money-mule detection.
* **Backend Ready:** In-memory graph engine already exists in [graph_service.py](file:///c:/Users/lenovo/OneDrive/Desktop/kurhh/Kurukshetra/backend/app/services/graph_service.py).

### 9. Collective Intelligence / User Scam Reporting (`brain.md` §32)
* **What it is:** A *"Report this recipient"* button on the UI. When clicked, it logs a scam report, increases the dispute count for that UPI ID in the database, and immediately raises the reputation risk for any future payment to that ID.

### 10. Multilingual / Hinglish Scam Detection (`brain.md` §35)
* **What it is:** Enable scam language analysis for Indian multilingual contexts:
  * Hindi / Hinglish messages: *"Aapka bijli connection kat diya jayega, turant pay karein"*, *"SBI KYC block ho gaya hai"*.
  * Shows language-aware AI reasoning in the explanation.
